  <files>

  <action>
Create `docker.ts` using `defineEnhancement()` following the exact pattern from eslint.ts and ci.ts.

**detect()**: Check for existing `Dockerfile` and `.dockerignore` in project root using `access()`. Return `{ installed: true }` if either exists.

**install()**: Generate framework-aware Dockerfile + .dockerignore.

Docker module needs its OWN framework detection beyond `ctx.framework` (which only covers web FrameworkIds). Implement a `detectDockerFramework()` function that:
- Checks `ctx.framework` first (for web frameworks: next, react/vue/svelte/astro → vite-style, remix)
- If `ctx.framework` is null, reads the filesystem:
  - `requirements.txt` or `pyproject.toml` with "fastapi" → fastapi
  - `requirements.txt` or `pyproject.toml` with "django" → django
  - `go.mod` → go
  - `Cargo.toml` → rust
  - Falls back to generic Node.js if `package.json` exists

Create a `FRAMEWORK_DOCKER_MAP` (similar to FRAMEWORK_ESLINT_MAP) with `DockerConfig` interface:
```typescript
interface DockerConfig {
  dockerfile: string
  dockerignore: string[]
}
```

Framework-specific Dockerfiles (per locked decisions and research):
- **Next.js**: Multi-stage with standalone output (node:22-alpine base, deps stage, builder stage, runner stage with nextjs user, EXPOSE 3000)
- **Vite/React/Vue/Svelte/Astro**: Static build with nginx (node builder + nginx:alpine runner, COPY dist to /usr/share/nginx/html, EXPOSE 80)
- **FastAPI**: Multi-stage Python (python:3.12-slim, pip install, uvicorn CMD, EXPOSE 8000, appuser)
- **Django**: Similar to FastAPI but with gunicorn CMD
- **Go**: Multi-stage (golang:1.23-alpine builder, CGO_DISABLED=0, scratch runner, EXPOSE 8080)
- **Rust**: Multi-stage (rust:1.82-slim builder, cargo build --release, debian:bookworm-slim runner, EXPOSE 8080)
- **Generic Node.js**: Multi-stage (node:22-alpine, npm ci, npm run build, node dist/index.js, EXPOSE 3000)

.dockerignore patterns per framework:
- All: `node_modules`, `.git`, `.env`, `*.md`, `.github`
- Node.js projects add: `dist`, `.next`, `.nuxt`, `.output`
- Python projects add: `__pycache__`, `*.pyc`, `.venv`, `venv`
- Go projects add: `vendor` (if not vendored)
- Rust projects add: `target`

Use `writeConfigFile()` from `_utils.ts` to write both files. No package installation needed (Docker is config-only). Use `readFile` for filesystem detection (checking requirements.txt content, go.mod existence).

**Test file**: Follow ci.test.ts pattern. Mock `node:fs/promises` (access, readFile, writeFile, mkdir). Test:
- detect returns false when no Dockerfile exists
- detect returns true when Dockerfile exists
- install generates Next.js Dockerfile when framework is 'next'
- install generates Vite Dockerfile for react/vue/svelte frameworks
- install generates FastAPI Dockerfile when requirements.txt contains fastapi
- install generates generic Node.js Dockerfile as fallback
- install writes .dockerignore with appropriate patterns

2. Generate `src/env.ts` (or `env.ts` if no src/ directory exists) with the generic t3-env pattern:
```typescript
import { createEnv } from "@t3-oss/env-core";
import { z } from "zod";

export const env = createEnv({
  server: {
    DATABASE_URL: z.string().url().optional(),
    NODE_ENV: z.enum(["development", "production", "test"]).default("development"),
  },
  runtimeEnv: process.env,
  emptyStringAsUndefined: true,
});
```
Per locked decision: generic pattern, no framework-specific client/server splitting.
